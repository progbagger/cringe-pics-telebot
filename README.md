# cringe-pics-telebot

Этот бот умеет присылать Тебе кринжовые картинки из мессенджера **WhatsApp**, которые, обычно, помечаются в нём тегом *часто пересылаемое*.

## Использование

На данный момент имеются следующие возможности:

- можно подписаться на одну из **четырёх** рассылок: **утреннюю**, **дневную**, **вечернюю** и **ночную**. При наличии подписи на соответствующую рассылку, бот будет присылать картинку, подходящую под название категории, в соответствующее время суток;
- можно вручную получить случайную картинку из категории (категорию также можно выбрать случайно, категория **random**);
- можно вызвать бота в любом чате через `@имя_бота day` (также доступны `morning`, `evening`, `night` и `random`) и выбрать конкретную картинку либо первый вариант `🎲 Выбрать случайную картинку` из результатов inline-поиска.

Для работы inline-режима владелец бота должен один раз включить его через [@BotFather](https://t.me/BotFather): выбрать команду `/setinline`, указать бота и задать текст-подсказку для поля ввода. Дополнительные переменные окружения не требуются.

Случайный вариант является первым обычным photo/GIF-result и сразу отправляет заранее выбранную картинку в текущий чат — без Mini App и перехода в личный чат с ботом. Telegram-клиенты показывают media-results в галерее и могут скрывать их `title`; в таком layout случайный вариант остаётся первым элементом, но подпись действия может быть не видна. Отдельная верхняя кнопка для мгновенной отправки произвольного inline-result в Bot API отсутствует.

## Технологии

Бот целиком и полностью написан на языке **Python** с использованием асинхронного бота из библиотеки **pyTelegramBotApi**. База данных пользовательских подписок хранится в соседней с ботом базе данных **PostgreSQL**.

## Деплой

После merge пулл-реквеста в `main` workflow **Deploy over SSH** автоматически
запускает деплой, когда workflow **CI** успешно проверил итоговый commit и в
пулл-реквесте изменились файлы приложения или production-сборки:

- `src/**`;
- `pyproject.toml` или `uv.lock`;
- `compose.yml`;
- `docker/**`.

Изменения только в документации, тестах и служебных файлах не запускают деплой.
Workflow также можно запустить вручную через `workflow_dispatch`; ручной запуск
не зависит от списка изменённых файлов.

Для workflow нужны GitHub Environment Secrets в environment **Deploy**:

- `DEPLOY_HOST` - адрес сервера;
- `DEPLOY_USER` - SSH-пользователь;
- `DEPLOY_SSH_KEY` - приватный SSH-ключ;
- `DEPLOY_PORT` - SSH-порт, если используется не `22`;
- `DEPLOY_PATH` - путь к checkout репозитория на сервере, если он отличается от `cringe-pics-telebot`.

На сервере автоматический workflow разворачивает конкретный commit, успешно
прошедший CI, и перезапускает сервисы через
`docker compose up -d --build --remove-orphans --force-recreate`.
