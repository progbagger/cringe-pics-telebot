# cringe-pics-telebot

Telegram-бот, который присылает кринжовые картинки и GIF из коллекции на Яндекс Диске. Медиа можно запросить вручную, получать по расписанию или отправлять в любой чат через inline-режим.

## Возможности

- `/start` и `/help` показывают актуальные категории, команды и клавиатуру быстрого доступа;
- кнопка категории отправляет случайное медиа из соответствующей папки;
- `/list` и `/subscriptions` позволяют подписаться на рассылки и отписаться от них. Бот отправляет случайную картинку из категории в указанное для неё время;
- `/timezone [+HH:MM]` показывает или меняет фиксированное UTC-смещение пользователя. Время всех категорий применяется как локальное время в выбранном часовом поясе; значение по умолчанию — `+07:00`;
- администраторы открывают закрытую панель командой `/admin` или отдельной reply-кнопкой и создают, редактируют и удаляют разовые рассылки;
- разовая рассылка без явно указанного UTC-смещения приходит в заданные дату и время отдельно по локальному часовому поясу каждого пользователя. Явное смещение, например `+07:00`, назначает единый момент отправки для всех;
- inline-запрос вида `@имя_бота day` ищет категории по части названия и показывает до 50 картинок и GIF. Первый результат `🎲 Выбрать случайную картинку` сразу отправляет случайно выбранное медиа;
- полученные при ручной или автоматической отправке Telegram `file_id` сохраняются в Redis, поэтому повторная отправка не требует повторной загрузки файла с Яндекс Диска;
- Redis также защищает рассылку от повторной отправки одному пользователю в одну и ту же минуту.

Категории не зашиты в коде: их названия, локальное время рассылки и папки с медиа хранятся в PostgreSQL. Выбранное UTC-смещение также хранится там отдельно для каждого пользователя. В PostgreSQL находятся и список администраторов, и разовые рассылки с историей попыток доставки. Поэтому настройки и запланированные сообщения сохраняются после перезапуска приложения.

Получатели разовой административной рассылки — все активные пользователи, которые взаимодействовали с ботом в private-чате, даже если они не подписаны ни на одну категорию. Если Telegram сообщает, что пользователь заблокировал бота или деактивировал аккаунт, пользователь исключается из следующих административных рассылок, но его часовой пояс и подписки сохраняются. Новое private-сообщение автоматически возвращает пользователя в активную аудиторию.

Для inline-режима владелец бота должен один раз включить его через [@BotFather](https://t.me/BotFather): выполнить `/setinline`, выбрать бота и задать текст-подсказку для поля ввода.

## Технологии

- **Python 3.14** и [aiogram 3](https://docs.aiogram.dev/) — асинхронный Telegram-бот в режиме long polling;
- **aiohttp** — работа с REST API Яндекс Диска;
- **PostgreSQL**, **SQLAlchemy 2** и **asyncpg** — категории и пользовательские подписки;
- **Redis** с **hiredis** — кэш Telegram `file_id` и защита рассылок от дублирования;
- **uv** — управление зависимостями и запуск приложения;
- **Docker Compose** — запуск бота, PostgreSQL и Redis;
- **pytest**, **Ruff** и **mypy** — функциональные тесты, линтинг и проверка типов в CI.

## Развёртывание на своём сервере

### Что понадобится

- Linux-сервер с Git, Docker Engine и Docker Compose v2;
- Telegram-бот и его токен от [@BotFather](https://t.me/BotFather);
- OAuth-токен Яндекс Диска с доступом к папке приложения;
- исходящие HTTPS-подключения к Telegram Bot API и API Яндекс Диска.

Входящий HTTP-порт для бота открывать не нужно: обновления Telegram он получает через long polling. Файл `compose.yml` публикует PostgreSQL на порту `4243`, а Redis — на `12312`; ограничьте доступ к ним сетевым экраном сервера, если эти порты не нужны извне.

### 1. Получить проект

```bash
git clone https://github.com/progbagger/cringe-pics-telebot.git
cd cringe-pics-telebot
```

### 2. Настроить переменные окружения

Создайте четыре файла. Они игнорируются Git и не должны попадать в репозиторий.

`docker/bot/.env`:

```dotenv
TELEGRAM_BOT_TOKEN=<токен Telegram-бота>
```

`docker/postgres/.env`:

```dotenv
POSTGRES_USER=cringe_bot
POSTGRES_PASSWORD=<надёжный пароль PostgreSQL>
POSTGRES_DB=cringe_bot
POSTGRES_HOST=postgres
```

`docker/redis/.env`:

```dotenv
REDIS_USERNAME=cringe_bot
REDIS_PASSWORD=<надёжный пароль Redis>
REDIS_HOST=redis
```

`docker/yandex/.env`:

```dotenv
YANDEX_DISK_TOKEN=<OAuth-токен Яндекс Диска>
```

Дополнительно в `docker/bot/.env` можно задать `LOG_LEVEL_NAME`, интервал проверки рассылок по категориям `SUBSCRIPTION_BROADCAST_INTERVAL_SECONDS` и интервал проверки административных рассылок `ADMIN_BROADCAST_INTERVAL_SECONDS`. Оба интервала по умолчанию равны 30 секундам; допустимы значения больше нуля и не более 60 секунд.

### 3. Подготовить медиа на Яндекс Диске

Создайте в папке приложения на Яндекс Диске каталоги категорий и загрузите туда изображения или GIF. Для стандартного набора это:

```text
morning/
day/
evening/
night/
random/
```

Имена каталогов должны совпадать со значениями `s3_directory_path` в таблице `subscription_types` из шага добавления категорий.

### 4. Запустить сервисы

```bash
docker compose run --rm bot uv run --isolated --no-dev --group migration alembic upgrade head
docker compose up -d --build
docker compose ps
docker compose logs -f bot
```

Миграции Alembic запускаются отдельной одноразовой командой и не входят в production-зависимости процесса бота. После запуска polling можно остановить просмотр логов сочетанием `Ctrl+C` — контейнеры продолжат работать.

### 5. Добавить администраторов

Список администраторов хранится в таблице `administrators`. Получите Telegram user ID нужного пользователя и добавьте его следующей командой, заменив `123456789` реальным значением:

```bash
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<'SQL'
INSERT INTO administrators (user_id)
VALUES (123456789)
ON CONFLICT (user_id) DO NOTHING;
SQL
```

Права применяются без перезапуска бота. Чтобы отозвать их, удалите только запись из `administrators`:

```bash
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<'SQL'
DELETE FROM administrators WHERE user_id = 123456789;
SQL
```

После добавления ID пользователь увидит кнопку **Админ-панель** при следующем `/start` или другом сообщении, которое показывает основную клавиатуру. Команда `/admin` доступна сразу. Для остальных пользователей команда и текст кнопки обрабатываются как неизвестное сообщение.

### 6. Добавить категории

Пример ниже создаёт стандартные категории и задаёт локальное время рассылок. Повторный запуск команды обновит существующие записи.

```bash
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<'SQL'
INSERT INTO subscription_types (name, time, s3_directory_path, search_aliases, created_at, updated_at)
VALUES
    ('random',  '00:00:00', 'random',  ARRAY['рандом', 'случайная'],          now(), now()),
    ('morning', '08:00:00', 'morning', ARRAY['утро', 'утренняя', 'с утра'],   now(), now()),
    ('day',     '13:00:00', 'day',     ARRAY['день', 'дневная'],              now(), now()),
    ('evening', '19:00:00', 'evening', ARRAY['вечер', 'вечерняя'],            now(), now()),
    ('night',   '23:00:00', 'night',   ARRAY['ночь', 'ночная'],               now(), now())
ON CONFLICT (name) DO UPDATE
SET time = EXCLUDED.time,
    s3_directory_path = EXCLUDED.s3_directory_path,
    search_aliases = EXCLUDED.search_aliases,
    updated_at = now();
SQL
```

Название категории используется в подписи кнопки и в inline-поиске; добавлять к нему `/` не нужно. `search_aliases` задаёт дополнительные термины только для inline-поиска: запрос сопоставляется с именем и каждым алиасом без учёта регистра, по частичному совпадению. Алиасы не создают отдельные кнопки или подписки и не влияют на обычные сообщения. Время указывается без UTC-смещения и наступает отдельно в локальном часовом поясе каждого подписчика, а путь задаётся относительно папки приложения на Яндекс Диске. Категория `random` в этом примере является отдельной коллекцией и отдельной рассылкой; при необходимости её можно удалить или настроить как любую другую категорию.

После инициализации отправьте боту `/start`, а при необходимости смените часовой пояс командой, например `/timezone +04:00`. Для проверки состояния и логов используйте:

```bash
docker compose ps
docker compose logs --tail=100 bot
```

Обновление установленной версии выполняется так:

```bash
git pull --ff-only
docker compose run --rm bot uv run --isolated --no-dev --group migration alembic upgrade head
docker compose up -d --build --remove-orphans
```

При запуске без Docker Compose сначала примените миграции командой `uv run --isolated --no-dev --group migration alembic upgrade head`, а затем запустите бота командой `uv run --no-dev bot`.

Данные PostgreSQL и виртуальное окружение бота сохраняются в Docker volumes `pg-data` и `bot-env`. Redis используется как восстанавливаемый кэш и отдельного volume не имеет.

## Управление категориями через админ-панель

Администратор может открыть **Админ-панель → Управление категориями**, выбрать категорию и заменить её поисковые алиасы без перезапуска бота. Алиасы вводятся по одному на строку; пробелы внутри строки сохраняются, а пустые строки и повторы без учёта регистра игнорируются. Кнопка **Очистить алиасы** удаляет весь дополнительный словарь, не меняя основное имя, кнопку, подписки, расписание или путь к медиа.

Первичную инициализацию и идемпотентное массовое обновление категорий удобнее выполнять SQL-командой из раздела выше. Админ-панель редактирует только `search_aliases` выбранной существующей категории.

## Разовые административные рассылки

Откройте `/admin`, выберите **Рассылки** и отправьте боту сообщение, которое нужно скопировать получателям. Поддерживаются типы сообщений, доступные методу Telegram `copyMessage`; исходное сообщение нельзя удалять до завершения рассылки.

Дата вводится одним из двух способов:

```text
20.08.2026 10:00
20.08.2026 10:00 +07:00
```

В первом варианте каждый получатель получает сообщение, когда `10:00` наступает в его сохранённом часовом поясе. Во втором все получают сообщение одновременно — в момент, соответствующий `10:00 UTC+07:00`. Допустимые фиксированные смещения: от `-12:00` до `+14:00`.

После даты бот предлагает указать до 1000 дополнительных Telegram user ID через пробелы, запятые или переносы строк. Этот список нужен, например, для разовой отправки пользователям, которых старая версия бота ещё не сохраняла. Дополнительные ID относятся только к выбранной рассылке и не делают пользователя постоянным получателем следующих. Если для ID ещё нет сохранённого часового пояса, используется значение по умолчанию `UTC+07:00`; явное смещение в дате по-прежнему задаёт один момент для всех. Шаг можно пропустить inline-кнопкой, а список — позднее изменить до начала отправки.

До начала первой доставки рассылку можно редактировать или удалить inline-кнопками. После начала отправки редактирование блокируется, чтобы пользователи разных часовых поясов не получили разные версии. Удаление является мягким: запись получает статус `deleted`, а завершённая рассылка — `completed`. Сами рассылки и результаты попыток остаются в PostgreSQL, хотя экран истории в текущей версии отсутствует.

Перед каждым сетевым запросом бот атомарно резервирует одну попытку для пары «рассылка — пользователь», поэтому повторная проверка scheduler-а не создаёт дубль. Автоматических повторов после ошибки нет; сбой одному получателю сохраняется в истории и не останавливает отправку остальным.

## Автоматический деплой через GitHub Actions

Workflow **Deploy over SSH** автоматически обновляет сервер после merge pull request в `main`, если workflow **CI** успешно проверил итоговый commit и были изменены файлы приложения или production-сборки:

- `src/**`;
- `docker/**`;
- `pyproject.toml` или `uv.lock`;
- `compose.yml`.

Изменения только в документации, тестах и служебных файлах деплой не запускают. Workflow также можно запустить вручную через `workflow_dispatch`; ручной запуск не зависит от списка изменённых файлов.

В GitHub environment с именем **Deploy** нужно создать secrets:

- `DEPLOY_HOST` — адрес сервера;
- `DEPLOY_USER` — SSH-пользователь;
- `DEPLOY_SSH_KEY` — приватный SSH-ключ;
- `DEPLOY_PORT` — SSH-порт, если используется не `22`;
- `DEPLOY_PATH` — путь к checkout репозитория на сервере, если он отличается от `cringe-pics-telebot`.

Перед первым автоматическим деплоем репозиторий, `.env`-файлы, категории PostgreSQL и папки Яндекс Диска нужно подготовить вручную по инструкции выше. Workflow разворачивает конкретный commit, применяет миграции отдельным one-shot контейнером и перезапускает сервисы через Docker Compose.
